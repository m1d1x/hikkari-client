# Методичка агента: перепись чужих входов (`ops census`)

Вопрос: у нас плохие настройки или плохие серверы, и у какого хостера входы живут. Сравниваем входы оплаченных владельцем сервисов с нашими релеями в той же сети, из той же точки замера.

Статус: код написан, тесты зелёные, **живого прогона ещё не было**. Первый прогон может найти ошибки: чини их, а не обходи. Особенно не проверен реальный sing-box с конфигом `proto`.

## Перед началом

Проверь, что выкачено:

```bash
scripts/ops release
```

```bash
scripts/ops testers
```

Нужно:
1. Hub с миграцией `019_census.sql` и переменной `CENSUS_EXIT_BASE` (публичный https-адрес hub, без неё выход не меряется, остальное работает). Переменную нужно добавить в `compose.hub.yaml`.
2. Клиент с `probe_targets` и `proto_targets` у тестера, Windows. `probe` и `proto` на других ОС отвечают ошибкой.
3. На машине оператора рядом лежат `hikkari-control` и `hikkari-client`: `census add` запускает парсер из `hikkari-client/engine/cmd/census-parse`.

Команды запускай из `hikkari-control`. Те же команды есть в MCP `hikkari-ops`: `census_add`, `census_add_addr`, `census_exit_link`, `census_probe`, `census_proto`, `census_report`. `census watch` только в шелле.

## Порядок

### Сервис с импортом подписки

Владелец передаёт URL. Не печатай его в ответах, логах и коммитах.

```bash
scripts/ops census add 'URL' --name haipik
```

```bash
scripts/ops census probe --who 002,005
```

```bash
scripts/ops census proto --who 002,005
```

```bash
scripts/ops census report
```

Подписка, требующая HWID, не разберётся: `census add` его не отправляет, потому что он занимает слот устройства. Решение по такой подписке за владельцем.

### Сервис без импорта (Sota и другие)

1. Вход: владелец включает приложение сервиса на компьютере, берём адреса из таблицы соединений этого процесса. Отдельной команды нет. С телефона так не снять.
2. Записать вход:

```bash
scripts/ops census add-addr --name sota --addrs 1.2.3.4:443,5.6.7.8:443
```

3. Выход: получить ссылку, владелец открывает её с включённым VPN.

```bash
scripts/ops census exit-link --name sota
```

4. Дальше `census probe` и `census report`. Протокол такому сервису не мерится, в строке `protocol: unknown`.

Адрес входа Sota не выводи из IP выхода: у каскадов это разные сети.

### Замеры по расписанию

```bash
scripts/ops census watch --who 002,005 --every 1h
```

Идёт на машине оператора, пока она не спит: пропуски видны как дыры в истории. Список входов сам не обновляется, повторяй `census add`.

## Как читать `report`

- `rows`: входы и наши релеи, одна сеть подряд, чужие первыми.
- `addr_alive`: последний TCP-счёт по точкам замера, `spb` и `tester:002`.
- `proto_alive`: последний счёт запросов через профиль.
- `alive_hours`: время между первым и последним удачным замером. Не время жизни, пока вход не умер.
- `exits`, `service_exits`: куда сервис выпускает трафик.
- `verdicts`: сравнение по сети и точке замера, **только по TCP**.

| Что видим | Что значит |
| --- | --- |
| чужой жив, наш мёртв | наши адреса или настройки |
| оба мертвы | адрес или сеть |
| адрес жив, протокол мёртв | режут протокол |
| вход и выход в разных ASN | каскад: хостера ищем по входу |

## Частые ловушки

- Вердикт только из `spb` мало что доказывает: это один маршрут Timeweb. Амстердамские «баны» 02.11 могут быть ложными, сверяй с тестерами.
- Живой TCP не значит живой туннель. Наши релеи пока без `proto`, поэтому сравнение протокола с ними не готово.
- Один живой поток из 12 всё равно читается как «жив». Смотри сам счёт: потоки дохнут по source port (`plans/2026-11-02-tcp-flow-loss.md`).
- Порт релея берётся из его последней записи. `ASN 0` значит, что Team Cymru не ответил или адрес не разрешился.
- Мак владельца выходит через Ригу: локальные замеры с него не считаются сетью РФ.
- `nekko-spb` сбрасывает SSH при частых подключениях. `census probe` держит одно соединение на прогон, не запускай его в цикле.
- Подпись хостера это ещё не вывод. Что брать, решает только тест (`plans/2026-11-01-vps-hosting-providers.md`).

## Что дальше с результатом

1. Выпиши хостеров и ASN, где чужие входы живут из сети тестера и `proto` проходит.
2. Сверь с `plans/2026-11-01-vps-hosting-providers.md`: там чего не брать.
3. Предложи владельцу одну пробную машину. Покупка только после его подтверждения.
4. Поставь наш релей и замерь в той же сети: чужой жив, наш мёртв значит, что дело в настройках.
5. Запиши результаты в `plans/2026-11-02-fleet-survival-and-domain-reuse.md`, отделяя замеры от предположений.

## Границы

- Только сервисы, которые оплатил владелец. Без сканирования подсетей и нагрузочных тестов: только адреса, которые выдал сам сервис. Hub не даёт мерить цель из одной точки чаще раза в 55 минут.
- URL и профили на hub только под cryptobox, в выводе их нет. Не добавляй их в логи, планы и коммиты.
- `census proto` на время пробы кладёт чужой профиль с секретами на диск машины тестера. Только режим тестера, обычным пользователям не запускать.
- Чужие профили не выдавать клиентам и не добавлять в нашу подписку.
- Покупки, пуш, деплой hub и релиз клиента только после подтверждения владельца.
- Тестера просим только о том, что нельзя сделать удалённо: «держи клиент открытым». Владельца просим только об оплате, URL и приложении сервиса.
