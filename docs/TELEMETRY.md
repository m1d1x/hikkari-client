# TELEMETRY

Телеметрия Hikkari: сколько людей пользуется, на чём ломается, что чинить. Это открытый контракт:
список полей ниже — публичное обещание, а не деталь реализации. Новое поле = правка схемы и этого файла,
иначе не мержим.

Статус: контракт v1; клиентский модуль `engine/core/telemetry` реализован, серверного приёма нет. Дата: 2026-10-31. Связано: `DOWNDETECTOR.md` (свой контракт и свой
транспорт отчётов; здесь только общий тумблер).

---

## 0. TL;DR

- Три потока: **события** (продукт), **ошибки**, **обращения** (с диагностикой по желанию).
- Один тумблер «Помогать развитию» в настройках. На старте проекта включён по умолчанию. Отдельного
  уведомления при первом запуске и экрана «что отправляется» нет (решение владельца 31.10).
- Тумблер управляет событиями, ошибками и даундетектором. Диагностика уходит **только** из формы обращения,
  после показа содержимого, независимо от тумблера.
- Никаких IP, доменов, адресов серверов, токенов подписки и связи с аккаунтом.

## 1. Тумблер и согласие

Состояние хранит движок (`telemetry.json` рядом с остальными настройками):

```json
{ "choice": null, "install": "t-3f9c…", "since": 1761900000 }
```

- `choice`: `null` — пользователь не выбирал, действует значение по умолчанию из сборки;
  `true`/`false` — явный выбор. Явный выбор никогда не перетирается: смена значения по умолчанию в будущей версии
  влияет только на тех, у кого `choice == null`.
- Значение по умолчанию зашито в сборку (`HIKKARI_TELEMETRY_DEFAULT`, сейчас `on`).
- Выключили → очередь событий и ошибок стирается, `install` удаляется; включили снова → новый `install`.
- Выключено → ноль сетевых запросов телеметрии и даундетектора. Проверяется тестом по сети.

## 2. Идентификатор установки

- `install`: 128 бит из `crypto/rand`, префикс `t-`. Постоянный, пока тумблер включён.
- Не выводится из железа, ОС, MAC, имени пользователя, токена подписки.
- Не совпадает и не связан с `install` даундетектора (тот ротируется раз в неделю, `DOWNDETECTOR.md` §2.3).
- Пересоздаётся при выключении тумблера и при установке начисто.

## 3. Общий конверт

Клиент шлёт пачки, не чаще раза в 15 минут и сразу при первом запуске:

```json
{
  "v": 1,
  "install": "t-3f9c…",
  "app": { "version": "1.0.4", "channel": "stable", "os": "macos", "os_major": "26", "arch": "arm64" },
  "events": [ … ],
  "errors": [ … ]
}
```

- `os`: `windows` | `macos` | `linux` | `android` | `ios`; `os_major` — только мажорная версия.
- Событие: `{"ts": 1761900060, "name": "connect", "fields": {"engine": "xray", "ok": true, …}}`.
- Время каждого элемента выровнено до минуты (`ts`, unix-секунды).
- Пачка ≤ 64 КиБ, ≤ 200 элементов.

## 4. События (полный список v1)

| `name` | Когда | Поля |
|---|---|---|
| `install` | первый запуск после установки начисто | — |
| `launch` | старт приложения | `cold` (bool) |
| `first_connect_ok` | первое успешное подключение за всю жизнь `install` | `engine`, `proto`, `secs_since_install` |
| `connect` | итог попытки подключения | `engine`, `proto`, `ok`, `secs` (до готовности), `error` (код §5, если не ok) |
| `daily_active` | раз в сутки, если приложение запускалось | `connected_minutes` (округлено до 10), `profiles` (0, 1, 2–5, 6+) |
| `engine_switch` | смена движка в настройках | `from`, `to` |
| `profile_import` | импорт профиля/подписки | `kind` (`link` \| `subscription` \| `file`), `ok`, `count` (0, 1, 2–10, 11+), `error` |
| `subscription_sync` | автосинк подписки | `ok`, `added`, `removed` (0, 1, 2+), `error` |
| `routing_apply` | применение маршрутизации | `mode` (`bypass` \| `proxy`), `ok`, `source` (`manual` \| `catalog` \| `import`), `error` |
| `update` | шаг автообновления | `step` (`found` \| `downloaded` \| `applied` \| `rolled_back` \| `failed`), `to_version`, `error` |
| `ui_open` | открыт экран | `screen` (фиксированный список: `settings`, `logs`, `routing`, `profiles`, `support`, `donate`) |
| `cta` | нажата кнопка оплаты/доната | `kind` (`subscribe` \| `renew` \| `donate`) |

- `engine`: `singbox` | `xray`. `proto`: `vless-reality` | `vless-xhttp` | `vmess` | `trojan` | `shadowsocks` |
  `hysteria2` | `other`.
- Счётчики — только корзинами из таблицы, точные числа не шлём.

## 5. Ошибки

```json
{ "ts": 1761900060, "code": "engine.start", "component": "singbox", "fp": "9e1c…", "msg": "…", "count": 3 }
```

- `code`: фиксированный словарь `<область>.<что>` (`engine.start`, `engine.crash`, `tunnel.dns`, `import.parse`,
  `sync.http`, `routing.compile`, `update.verify`, `service.ipc`, `ui.exception`, …). Новый код = правка этого файла.
- `component`: `engine` | `singbox` | `xray` | `service` | `updater` | `ui`.
- `fp`: отпечаток = sha256 от `code` + сообщения после нормализации (числа, пути, адреса → плейсхолдеры).
  Одинаковые ошибки в пределах пачки склеиваются в `count`.
- `msg`: сообщение **после вычистки** (§7), обрезано до 300 символов. Стек для Dart/Go — только имена
  функций и файлов приложения, без аргументов.

## 6. Обращения

Форма «Написать в поддержку» в клиенте — основной путь; ссылка на Telegram-поддержку рядом.

```json
{
  "v": 1,
  "text": "…",
  "contact": "@nick | mail | null",
  "app": { … как в §3 … },
  "diag": null
}
```

- `install` не отправляется: обращение не связывается с телеметрией.
- `diag` (если пользователь поставил «Приложить диагностику»): хвост логов ≤ 2000 строк и ≤ 512 КиБ,
  активный движок и его конфиг, состояние туннеля, список профилей **без адресов и ключей** (тип, протокол),
  маршрутизация (режим, число правил). Всё проходит вычистку §7.
- Перед отправкой пользователь видит пакет целиком и может отменить.
- Ответ хаба — номер обращения `H-XXXX`; клиент показывает его, по номеру можно продолжить в Telegram.
- Работает при выключенном тумблере: это явное действие пользователя.

## 7. Вычистка

Одна функция в движке, через неё проходит всё, что уходит из §5 и §6, до записи в очередь:

- IPv4/IPv6 → `<ip>`; домены и URL → `<host>` (кроме фиксированного списка наших: `hikkari.net`, Cloudflare probe);
- UUID, ключи Reality/WireGuard, пароли, `pinSHA256`, токен подписки (`/sub/<token>`) → `<secret>`;
- пути с именем пользователя → `~`;
- порты, привязанные к адресу, удаляются вместе с адресом.

Покрывается тестом на корпусе реальных строк из логов sing-box, Xray, службы и апдейтера: ни одна строка
корпуса не содержит исходного секрета после вычистки.

## 8. Никогда не отправляем

IP пользователя (прямой и выхода), адреса и ключи серверов, токены подписки, домены и сайты, куда ходит
пользователь, правила маршрутизации по содержимому (домены, приложения, папки), список установленных
приложений, железо кроме `arch`, MAC и любые аппаратные ID, имя пользователя, связь с аккаунтом подписки.

## 9. Транспорт и сервер

- Хаб: `POST /v1/events` (§3), `POST /v1/support` (§6). Тот же публичный хост, что даундетектор.
- Отправка через туннель, если он поднят; иначе напрямую. Очередь на диске: ≤ 1 МиБ и ≤ 7 дней,
  при переполнении выкидываются самые старые события, ошибки — по одной на `fp`.
- Повтор с экспоненциальной паузой (1 мин → 1 ч), сеть не блокирует UI и подключение.
- Сервер: rate-limit по `install`; IP запроса не пишется ни в БД, ни в логи прокси.
- ClickHouse: сырые события и ошибки — **90 дней** (TTL), дальше дневные агрегаты
  `день × версия × ОС × движок × событие/код` с числом установок. Обращения — в Postgres.
