# DOWNDETECTOR

Общий даундетектор: показывает, упал сервер **у всех**, **только у твоего провайдера** или **только у тебя**.
Наш сервер собирает результаты проб от клиентов и сам пробует серверы снаружи. По сути это свой
Downdetector с полным датасетом по РФ: какой провайдер, какой протокол, что и когда легло.

Статус: план. Дата: 2026-10-30. Связано: `AUTODEPLOY-ROADMAP.md` (это первый кусок того же control-plane).

---

## 0. TL;DR

- Своих точек наблюдения по миру **не строим**. Данные дают клиенты, плюс одна внешняя проба с нашего сервера.
- Клиент **не делает новых проб**: отправляет то, что уже меряет `engine/core/uptime` (раз в 30 с).
- Сервер: один VPS **вне РФ**, Go + SQLite. Хранит только «провайдер / страна / сервер / результат», без IP юзеров.
- Сначала только для друзей (по инвайтам), публичная страница статуса потом.

## 1. Вердикт

Считаем по каждому серверу за скользящее окно (15 мин):

| Внешняя проба | Другие юзеры | Ты | Вердикт |
|---|---|---|---|
| ❌ | ❌ у всех | ❌ | `server_down`: сервер упал |
| ✅ | ❌ у твоего ASN, ✅ у других | ❌ | `isp_block`: режет твой провайдер |
| ✅ | ❌ во всей РФ, ✅ вне РФ | ❌ | `country_block`: блок по стране |
| ✅ | ✅ | ❌ | `local`: проблема у тебя (сеть / конфиг) |
| ✅ | ✅ | ✅ | `ok` |
| — | мало данных | — | `unknown`: честно говорим «не знаем» |

Порог «мало данных»: меньше N разных установок за окно (на старте N=2, потом подберём).

## 2. Клиент (engine)

### 2.1 Тег источника пробы
Сейчас в `uptime/probe.go` три сигнала сливаются в один `RttMs`. Добавляем в `Sample` поле `src`:
- `tunnel`: Clash delay через туннель (сильный сигнал: трафик реально проходит);
- `tcp`: TCP-connect к порту (слабый: хост жив, но DPI может резать протокол);
- `icmp`: пинг (самый слабый).

Для вердикта `isp_block` годится только `tunnel`: TCP-коннект проходит и при блокировке по DPI.

### 2.2 Свой провайдер (ASN)
Отчёты идут через туннель, поэтому сервер видит IP выхода VPN, а не провайдера юзера.
Значит, ASN определяет **сам клиент**:
- прямой IP уже знает `health` (`directIP`);
- ASN и город/область берём из локальной базы `engine/core/netinfo` (DB-IP Lite, CC BY 4.0 — нужна атрибуция в «О приложении»), страну из `geoip`;
- мелкие города сворачиваются в область **при генерации базы**: более точных данных в бинарнике просто нет;
- **на сервер уходят только `asn` + `country` + `region`** (город или область, §4.1), сам IP никуда не уходит.

### 2.3 Отчёт
Раз в 5 минут, пачкой, агрегатом по серверу (сырые сэмплы не шлём):

```json
{
  "install": "r-7f3a…",
  "asn": 12389, "country": "ru", "region": "msk",
  "window": [1761800000, 1761800300],
  "servers": [
    {"id": "n:fra-1", "proto": "vless-reality", "src": "tunnel", "ok": 9, "fail": 1, "rtt_p50": 74}
  ]
}
```

- `install`: случайный id, **ротируется раз в неделю**. Нужен только для дедупа и rate-limit.
- `id` сервера:
  - `n:<node>`: наши ноды некко;
  - `s:<sha256(host:port:proto)>`: серверы из подписок;
  - приватные серверы **не отправляем без opt-in**. Хэш тут не спасает: IPv4 с портами перебирается.
- Отправка через туннель, если он поднят. Иначе копим в очереди (лимит ~1 ч) и шлём позже.
- Выключается одним тумблером в настройках.

### 2.4 FFI
- `downdetector.status(profile)` → вердикт + короткий текст для UI;
- `downdetector.setEnabled(bool)`.

## 3. Сервер

- **API**
  - `POST /v1/reports`: приём пачек (auth: инвайт-токен на этапе друзей);
  - `GET /v1/status?ids=…&asn=…`: вердикты для клиента;
  - `GET /v1/overview`: агрегат «что лежит в РФ по провайдерам» (для нас, потом для публичной страницы).
- **Внешний проббер**: тот же `uptime.LiveProbe`, запущенный на сервере. Пробует все известные `n:` и `s:` серверы
  раз в минуту. Это колонка «внешняя проба» в таблице вердиктов.
- **Хранение (SQLite)**
  - сырых отчётов нет (§4.2);
  - `rollup_hourly(hour, asn, country, region, server_id, proto, src, ok, fail, rtt_p50, installs)`, храним долго: это и есть датасет;
  - IP запросов в логах веб-сервера **не пишем**.
- **Деплой**: docker compose на одном VPS (вне РФ), домен за CDN, чтобы эндпоинт было сложнее заблокировать.

## 4. Приватность и риски

| Риск | Что делаем |
|---|---|
| Сервер узнаёт, кто к чему подключается | только ASN + страна, `install` ротируется, приватные серверы по opt-in |
| Хэш адреса сервера перебирается | не считаем его анонимизацией, приватные серверы без opt-in не шлём |
| Наш эндпоинт заблокируют | отчёты через туннель + очередь, домен за CDN |
| Мусорные / фейковые отчёты | инвайт-токены, rate-limit по `install`, вердикт по числу разных установок, а не отчётов |
| Мало данных на старте | вердикт `unknown` вместо выдуманного |
| Лишняя нагрузка на туннель | новых проб нет, 1 запрос в 5 мин |

## 4.1 Что собираем — открытый контракт

Код клиента может стать открытым, поэтому список полей — это публичное обещание, а не деталь реализации.

**Отправляем (полный список):** случайный `install` (ротация раз в неделю), ASN, страна, город или область (см. ниже),
окно в 5 мин, по каждому серверу: `id`, протокол, источник пробы, `ok`/`fail`, медианный RTT.

**Никогда не отправляем:** IP (ни прямой, ни выхода), адреса приватных серверов, доменов/сайтов, куда ходит юзер,
трафик, логи, список приложений, железо/ОС, аккаунты и любые постоянные идентификаторы устройства.

Правила:
- Отчёт собирает **одна функция** со строгой схемой. Новое поле = правка схемы + этого раздела, иначе не мержим.
- В приложении есть экран «Что отправляется», где показан **последний отчёт как есть** (JSON).
- **Город или область:** город отправляем, только если он в списке крупных (≈ миллионники). Иначе только область,
  чтобы связка «маленький город + маленький провайдер» не сужала круг до пары человек.
- Сервер не хранит сырые отчёты, только агрегаты при ≥k разных установок (§4.2).

## 4.2 Хранение на сервере

Принцип: **сырые отчёты не храним вообще.** Нет данных — нечего украсть, изъять или расшифровать.

- Отчёт пришёл → сервер прибавил его к суммам в памяти → сам отчёт выбросил.
- На диск пишутся только **агрегаты**: провайдер × регион × сервер × протокол × час (`ok`, `fail`, RTT, число установок).
  Без `install`, без отдельных отчётов. По ним юзера не восстановить.
- Агрегат по провайдеру/региону показываем и храним только при ≥k установок, иначе сворачиваем в `other`.
- `install` живёт только в памяти, для дедупа и rate-limit в текущем окне, на диск не попадает.
- Время выровнено по 5-минутному окну.
- Секреты сервера (ключи, инвайт-токены, доступы) — в SOPS (`age`).

Чем платим: старые данные нельзя пересчитать по новой логике вердикта. Для даундетектора не критично.

Предел: если атакующий сидит на живом сервере, он видит новые отчёты, пока там сидит. Поэтому сам отчёт минимальный (§4.1).

## 5. Фазы

### Phase 0 — клиент без сервера ✅
- [x] `src` в `uptime.Sample` и в `probe.go` (`tunnel` / `tcp` / `icmp`).
- [x] Локальная база ASN + город/область (`engine/core/netinfo`), определение по `health.DirectIP()`.
- [x] Город/область: список миллионников в `netinfo/gen`, остальные сворачиваются в область (§4.1).
- [x] Сборка отчёта одной функцией `downdetector.Build`, очередь `downdetector-outbox.json` (≤12 отчётов),
      `install` с ротацией раз в неделю, FFI: `DowndetectorSettings` / `SetDowndetectorSettings` / `DowndetectorLastReport`.
- [ ] Сгенерировать базу (сеть сессии не пускает к DB-IP, делается локально):
      `go run ./core/netinfo/gen -asn dbip-asn-lite-YYYY-MM.csv.gz -city dbip-city-lite-YYYY-MM.csv.gz -out core/netinfo/data`.
- [x] Профиль помнит, откуда он (`origin`): `subscription` (скачан по http(s)-подписке), `link` (ссылка или
      вставленный конфиг), `nekko` (наша нода, зарезервировано). В отчёт по умолчанию идут только `subscription`
      и `nekko`, остальные — при `share_private: true`. Старые профили без `origin` считаются личными
      (чтобы попасть в отчёт, подписку нужно переимпортировать).

## 6. Решения и открытые вопросы

Решено:
- **Где сервер**: на нашей инфре, вне РФ.
- **Код сервера**: отдельный **закрытый** репо. Здесь только клиентская часть и протокол отчёта.
- **Гранулярность**: ASN + город для крупных городов, иначе область (§4.1).
- **Хранение**: сырые отчёты не храним, на диске только агрегаты по часам (§4.2).
- **Что собираем**: фиксированный открытый список полей + экран «Что отправляется» (§4.1).

Открыто:
1. Значение k и список «крупных городов».
2. **Включено по умолчанию или opt-in?** Для друзей включено. Для релиза решаем вместе с вопросом,
   открываем ли код клиента.
3. **Открывать ли код клиента.** Если открываем, перед публикацией проверить историю коммитов на чувствительное
   (или публиковать с чистой историей).
